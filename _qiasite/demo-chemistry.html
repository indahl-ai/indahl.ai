Chemistry: molecular energy

A pharma or materials R&D team that computes molecular ground-state energies on IBM hardware with dynamic circuits, and needs a number it can trust before moving to bigger molecules.

Their run and ours

The hydrogen molecule's energy by phase estimation: five phase bits read mid-circuit with feedforward, IBM's default layout, bits taken as read. Our run is the same circuit on the same qubits, read with our calibration.

Energy error, in thousandths of a hartree. Lower is better. Six copies per chip, run 1.

What we changed

The circuit is almost all two-qubit gates, so how often each phase bit comes out right is set by gate error. Before the run we measured the error of the two gates it uses and read each of its three qubits' readout that day. The correction uses those measured values. Our correction and the stated one use the same readout table, so the gap between them is the gate error alone. Nothing is added to the client's circuit.

How it was checked

  • Hardware only: every number comes from runs on ibm_kingston, ibm_fez and ibm_marrakesh. No simulated result is quoted.
  • The plan, its settings and the margins for each outcome word were committed before the run.
  • IBM's automatic changes were off on our arm and read back from each job: no gate or measurement twirling, no dynamical decoupling, no error mitigation.
  • Any value we measured was applied only in a later job, never in the job that measured it.
  • Each result was fired twice, hours apart, with the same plan and fresh calibration jobs.

Outcome. Ours against the client: BELOW (lower error, and more all-bits-right shots) on all three chips, in both runs. Ours against a correction from IBM's stated figure: lower every time, CONSISTENT on energy; on all-bits-right, BELOW or CONSISTENT.
