Method

How a reading is made.

Stated value first, then the measurement, then the interval, then the outcome. The comparison is fixed before any data is read.

Four outcomes

Against the stated value, with both the zero and the size that would matter tested.

ABOVEThe measured value sits above the stated value, outside the interval.
BELOWThe measured value sits below the stated value, outside the interval.
CONSISTENTThe stated value sits inside the interval. The bound is printed.
CANNOT TELLThe data cannot separate the stated value from the size that would matter.
The stated value, named
Each line names what the published figure is (its definition, its averaging and the record it comes from) before anything is compared against it.
The record the job ran under
IBM states that its published properties come from calibration run about once a day (IBM tutorial). Each measured value is compared with the record in force when its job ran, not a daily median.
Intervals
Brackets are 95% intervals unless the row names another; each row names its interval and the units it is taken over (qubits, pairs, trials or jobs). A result inside the interval is reported as consistent, with the bound printed. Where a row tests a size that matters, it states that margin.
Comparisons built in advance
The comparison arm, the counts and the outcome rule are written down before the data is read. Anything defined after the data is labeled as such.
Easily repeatable evidence
Job IDs, raw counts, code and checksums ship with every report. The Heuremen Standard behind these rules is at indahl.ai/standard.
