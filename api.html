Measurements as tools

The developer guide, with quickstart, the answer format, receipts and the OpenAPI document: Developers.

Every live desk on this site can be read by an agent or a script, with no key and nothing to install. Each answer carries its source page, the time it was read and the terms. Outcomes are above, below, consistent or cannot tell, relative to what was stated. Nothing here writes anything.

Add it to an agent

The MCP server is at https://indahl.ai/mcp and speaks the Model Context Protocol over HTTP. In Claude Code:

claude mcp add --transport http indahl https://indahl.ai/mcp

Any client that takes a remote MCP server can use the same address. Start with list_divisions.

Tools

ToolReturns
list_divisionsList every division of indahl.ai with a one-line description and its page.
qia_auditQIA, the Quantum Idle Audit: the audit of the calibration IBM publishes for each IBM Quantum processor, newest record and every saved record since 28 Oct.
find_studySearch the List of published studies that QIA (quantum hardware), IRIS (language models) or SAGAR (gravitational-wave papers) has read and indexed.
link_rotCode and data links stated in arXiv abstracts and comments (categories cs.LG, cs.CL, cs.CV, quant-ph and stat.ML, hosts GitHub, GitLab, Hugging Face, Zenodo and Bitbucket) against whether they resolve now: per submission year and per host, links read, live, gone or host missing, blocked and timed out counted apart, the rot share with a 95% interval and the outcome.
arxiv_version_driftFor every arXiv study that QIA and IRIS index: whether a later arXiv version exists and whether the revision changed what we read (abstract numbers, title or wording, withdrawal), by class and by month indexed, with the studies whose abstract numbers changed and the numbers each version states.
all_tests_side_by_sideThe headline test of every live page in one table: what was compared, how many failed, the share with its 95% interval, and the outcome each page's own rule gave, ordered by outcome.
paper_checkCheck one paper by DOI or arXiv id: retraction, correction and expression-of-concern notices registered in Crossref (from publishers, and entries Crossref attributes to Retraction Watch), the current arXiv version, whether the arXiv comment says the paper was withdrawn, whether a page answers at each code and data link stated in the abstract (the contents are not read), and whether QIA or IRIS indexed it.
paper_statisticsRead the full text of one arXiv paper from arXiv's HTML version and recompute every reported t, F, chi-square, r and z statistic and every count-and-percentage pair from the paper's own numbers, references cut.
check_reported_statisticsRecompute the statistics in text pasted from a paper: every reported t, F, chi-square, r and z statistic with its p value, from the statistic and its degrees of freedom (the method of statcheck), and every count-and-percentage pair such as "45 of 120 (37.5%)" from its counts, allowing for rounding.
what_changedWhich live checks on indahl.ai changed since a given time.
package_checkCheck one PyPI project by name, live, with the rules of the PKGLICENSE and PKGINSTALL desks: whether the newest release carries files pip can install on any platform (an sdist or a universal wheel), is limited to certain platforms, is yanked or has no files, and whether the license the package states agrees with the license of its linked GitHub repository, compared by family.
model_checkCheck one Hugging Face model by id, live, with the rules of the HFSIZE and HFLICENSE desks: whether the size in its name agrees with the parameter count of its safetensors weights (0.70 to 1.35 times), and whether the license on its card agrees with the license file in the repository, compared by family.
qia_calibration_checkCheck the calibration record IBM publishes for an IBM Quantum processor, for the qubits a circuit will use.
qia_run_checkFor a run already done on an IBM Quantum processor: which published calibration record was in force at the start, every record IBM stamped during the run window that the indahl.ai index saw, each change in T1, T2 and the readout error figures on the run's qubits, records with the same stamp but different figures (CONFLICT), and the package flags on the record in force.
qia_qubit_historyEvery distinct T1, T2 and readout-error measurement IBM published for one qubit of an IBM Quantum processor in the indahl.ai saved index (up to 30 days), deduplicated by IBM's measurement date.
qia_measuredFor an IBM Quantum processor and the qubits a circuit will use: IBM's stated readout error and T1 with the entry date and age, beside our latest hourly measurement of the same qubit (value, 99.9 % / 99.99 % interval, job id, window in UTC, job file URL), the outcome word of the published calibration rule with a plain sentence of which way it points, and the qubit's last hourly runs (median, range, outcome counts, only runs that passed known-good).
quote_checkFinds quoted spans in a draft (straight and curly double quotes, lines marked with ">") and searches each in a source given as a DOI, arXiv id, URL or pasted text.
number_checkExtracts each number in a report (with %, currency, separators, decimals, k/M/B suffixes) and its context words, and looks for it in a source given as a DOI, arXiv id, URL or pasted text.
source_checkExtracts DOIs, arXiv ids and URLs from text or a refs list and reads each: RESOLVES, BROKEN, RETRACTED, CORRECTED or CANNOT TELL, with Crossref title and registered notices, the arXiv current version, or the HTTP status.
claim_wording_checkRule-based scan of result sentences for wording patterns such as proof language, causal verbs, "no effect" from non-significance, "significant" without a test, first/novel, always/never/all, "the same" for a non-difference, robust and clearly.
standards_cardBuilds a Standards (F1 to F6) card for a paper by arXiv id or DOI, or for pasted text.
interval_verdictCompares an estimate and its interval (low and high, or se with a level) with a stated value, and with the stated value plus or minus a size that would matter.
margin_checkFor a parameter with a stated value and uncertainty, computes the margin to each point where a conclusion fails, in absolute, relative and sigma units, and the one-tail probability the parameter lies past it under a normal assumption.
triangulate_readingsTakes two or more readings (value with se or low/high).
controls_checkChecks a list of controls before a run (at least one positive and one negative, each expected outcome different from the null, hardest positive and independence flags when supplied) and after a run (each control PASSED, FAILED or CANNOT TELL against its expected outcome).
two_explanationsTallies an evidence ledger for two named explanations.
eval_setup_checkA decided ABOVE or BELOW requires all eleven setup fields named and matching on both sides, otherwise a value gap reads CANNOT TELL. Compares a claimed evaluation setup with ours field by field (harness, prompt format, chat template, few-shot, max tokens, temperature, stop, extraction rule, dataset version, items, seeds): MATCH, DIFFERS, UNNAMED_BY_CLAIM, UNNAMED_BY_US or UNNAMED_BY_BOTH (named by neither side, not compared, but it still keeps the outcome from reading as a clean match).
verify_landedReads an effect back from the place it should have landed instead of trusting an exit code: a live URL (status, optional sha256 of the body, optional expected text), a GitHub commit (exists, and on a named branch), a GitHub release (tag, assets), a PyPI release (version, files, upload time), an npm version, or a DNS TXT record (Cloudflare DNS-over-HTTPS).
prereg_checkFor a public GitHub repository, finds the oldest commit touching a plan file and the oldest touching a results path (or compares the plan with a stated first run time), checks the repository PushEvent records (the host's own record, last 90 days only) and reports PLAN_FIRST, RESULTS_FIRST, SAME_PUSH or CANNOT TELL with both times and which record each came from.
batch_planLists the items of a big job from a sitemap URL (sitemap index followed one level), a public GitHub repository tree (optional path and ext filter) or an items array, de-duplicates and sorts them (cut at 5000, reported when cut), cuts them into batches of batch_size (default 25) with index ranges, and returns a manifest sha256 over the sorted list for use with batch_merge_check.
batch_merge_checkCompares result ids with a manifest list by exact id: MISSING (in the manifest, no result), DUPLICATE (more than one result), EXTRA (result not in the manifest).
relay_plan_checkRule-based check of a list of stages {name, needs, lane, deadline_minutes, writes_exit_code_to, retries}: unknown dependencies, cycles (the cycle is named), stages without a deadline, stages without a recorded exit-code file, two stages writing the same exit file, and lanes over a given limit in a wave.
correction_checkCompares original and corrected text by sentence and number, writes a corrections-ledger entry (what, was, now, logged_at, why), then fetches up to 20 named public pages and reports per page UPDATED, STILL_OLD, BOTH_PRESENT, NEITHER_FOUND or CANNOT TELL, by normalized match on the changed sentences.
check_block_validateValidates a pasted check block (CHECK.json or text lines "REQ-01: holds: ...") against the recount requirements of the Heuremen LLC Standards, read from https://indahl.ai/standard/standard_v1.json at call time.
reproduce_checkFetches a file published on indahl.ai (a desk data pack by desk name, or any published file by url) and its .sha256, computes the sha256 of the bytes and reports MATCH, MISMATCH or CANNOT TELL. Also hashes the copy in the public GitHub repository indahl-ai/indahl.ai and compares it with the site copy.

The same tools as plain JSON

curl 'https://indahl.ai/api/v1/qia_audit'
curl 'https://indahl.ai/api/v1/list_divisions'
curl https://indahl.ai/api/v1

The OpenAPI description is at /api/openapi.json. Tool responses are cached for a minute and the tool list and the OpenAPI file for ten minutes.
