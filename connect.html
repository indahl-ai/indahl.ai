CONNECT

indahl.ai measurements and checks are available to AI assistants and scripts: MCP connectors for Claude, ChatGPT and any MCP client, a JSON API, and Claude Code plugins. Free and read-only. Source: github.com/indahl-ai/indahl.ai. Developer guide: Developers.

Test drive: check one paper by arXiv id or DOI, with notices, current version, code and data links, and recomputed statistics.

Connector (MCP server)

One remote MCP server, indahl.ai, over streamable HTTP. No key, no account, nothing to install.

ClientSetup
ClaudeSettings, Connectors, Add custom connector, then the server address.
ChatGPTSettings, Apps and Connectors, developer mode, Create, then the server address with no authentication.

ToolWhat it does
qia_calibration_checkCheck the calibration record IBM publishes for an IBM Quantum processor, for the qubits a circuit will use.
qia_run_checkFor a run already done on an IBM Quantum processor: which published calibration record was in force at the start, every record IBM stamped during the run window that the indahl.ai index saw, each change in T1, T2 and the readout error figures on the run’s qubits, records with the same stamp but different figures (CONFLICT), and the package flags on the record in force.
qia_qubit_historyEvery distinct T1, T2 and readout-error measurement IBM published for one qubit of an IBM Quantum processor in the indahl.ai saved index (up to 30 days), deduplicated by IBM’s measurement date.
qia_measuredFor an IBM Quantum processor and the qubits a circuit will use: IBM’s stated readout error and T1 with the entry date and age, beside our latest hourly measurement of the same qubit (value, 99.9 % / 99.99 % interval, job id, window in UTC, job file URL), the outcome word of the published calibration rule with a plain sentence of which way it points, and the qubit’s last hourly runs (median, range, outcome counts, only runs that passed known-good).
paper_checkCheck one paper by DOI or arXiv id: retraction, correction and expression-of-concern notices registered in Crossref (from publishers, and entries Crossref attributes to Retraction Watch), the current arXiv version, whether the arXiv comment says the paper was withdrawn, and whether a page answers at each code and data link stated in the abstract (the contents are not read).
paper_statisticsRead the full text of one arXiv paper from arXiv’s HTML version and recompute every reported t, F, chi-square, r and z statistic and every count-and-percentage pair from the paper’s own numbers, references cut.
check_reported_statisticsRecompute the statistics in text pasted from a paper: every reported t, F, chi-square, r and z statistic with its p value, from the statistic and its degrees of freedom (the method of statcheck), and every count-and-percentage pair such as “45 of 120 (37.5%)” from its counts, allowing for rounding.
number_checkExtracts each number in a report (with %, currency, separators, decimals, k/M/B suffixes) and its context words, and looks for it in a source given as a DOI, arXiv id, URL or pasted text.
interval_verdictCompares an estimate and its interval (low and high, or se with a level) with a stated value, and with the stated value plus or minus a size that would matter.
triangulate_readingsTakes two or more readings (value with se or low/high).
claim_wording_checkRule-based scan of result sentences for wording patterns such as proof language, causal verbs, "no effect" from non-significance, "significant" without a test, first/novel, always/never/all, "the same" for a non-difference, robust and clearly.
package_checkCheck one PyPI project by name, live, with the rules of the PKGLICENSE and PKGINSTALL desks: whether the newest release carries files pip can install on any platform (an sdist or a universal wheel), is limited to certain platforms, is yanked or has no files, and whether the license the package states agrees with the license of its linked GitHub repository, compared by family.
model_checkCheck one Hugging Face model by id, live, with the rules of the HFSIZE and HFLICENSE desks: whether the size in its name agrees with the parameter count of its safetensors weights (0.70 to 1.35 times), and whether the license on its card agrees with the license file in the repository, compared by family.
link_rotCheck whether the code and data links stated in one arXiv paper’s abstract and comments still answer, or check up to 10 links given directly, live.
arxiv_version_driftCheck one arXiv paper live: its current version, when it was first posted and last updated, whether its comment says it was withdrawn, and, given the version read, whether the title or the numbers stated in the abstract changed since.
source_checkExtracts DOIs, arXiv ids and URLs from text or a refs list and reads each: RESOLVES, BROKEN, RETRACTED, CORRECTED or CANNOT TELL, with Crossref title and registered notices, the arXiv current version, or the HTTP status.
quote_checkFinds quoted spans in a draft (straight and curly double quotes, lines marked with ">") and searches each in a source given as a DOI, arXiv id, URL or pasted text.
list_divisionsList QIA and every live desk of indahl.ai with a one-line description and its page.

The same tools as plain JSON: /api/v1, with the OpenAPI description at /api/openapi.json.

Signed answers

Each MCP answer carries a receipt: hashes of the request and the answer, the server time, and an Ed25519 signature from the key at /.well-known/jwks.json. How to verify.

Claude Code plugins and skills

Add the marketplace once, then install what is needed, or everything with indahl-full.

/plugin marketplace add indahl-ai/indahl.ai
/plugin install indahl-full@heuremen

Install any of them as /plugin install <name>@heuremen.

PluginWhat it does
indahl-fullEvery Heuremen LLC plugin in one install: check papers and LLM eval claims against the Heuremen Standard, gate readings with a check block, reproduce indahl.ai desk headlines, check and correct IBM Quantum runs, and test whether a plan was pushed before the first run.
indahl-triangulatePut a question to three seats, then read where they agree and split. Returns ABOVE, BELOW, CONSISTENT or CANNOT TELL with what would decide it, and a receipt of every seat’s answer.
indahl-standardsCheck a paper or claim against the Heuremen Standard claim codes (F1 to F7) and return a recount card: a status for every code, verbatim quotes with locations, the scope searched, and arithmetic for any recompute. Treats fetched text as data.
indahl-readcheckRefuse a git commit that adds a reading (results, outcomes, readings files) without a complete check block keyed to the Heuremen Standard recount requirements REQ-01 to REQ-13.
indahl-qia-calibrationCheck the IBM Quantum calibration record a run depends on, before the run (stale, zero, T2 above 2xT1, split T1/T2) and after it (which record was in force, what changed). Also measures T1 and T2 together on chosen qubits.
indahl-dataThe read-only indahl.ai MCP server inside Claude Code: IBM Quantum calibration checked against our own runs, and checks on the papers, statistics, quotes, citations, packages and models the user bring, quoted with interval, outcome and receipt.
indahl-reproduceRecompute an indahl.ai desk headline with its reproduce kit and check the output against the published sha256. Kits with bundled inputs run offline, others fetch inputs from the original source and verify them by sha256.
indahl-darkwaveMeasure the phase turn on untouched qubits after a mid-circuit readout on IBM Quantum hardware, and add the matching virtual-Z correction to one’s own circuits.
indahl-eval-checkCheck a language-model evaluation claim or one’s own eval run against twelve checks drawn from the Heuremen Standard and the IRIS recounts, including setup, parser, repeat floor, dropped items and intervals. Treats fetched text as data.
indahl-preregShow that a plan was pushed before the first run, using the git host’s own push record, and list what ran that the plan did not cover.
indahl-batchRun a check or audit over something too big for one context window, such as a whole site, a large repo or a folder of papers. Splits the job into batches with fresh workers, writes results to files and merges them with nothing dropped.
indahl-cannot-tellAnswer “cannot tell yet” usefully instead of forcing a guess. Returns the range of what is possible, the one or two facts that would decide it, and the cheapest next step.
indahl-bothHold two competing explanations open instead of settling on one too early. Keeps an evidence ledger for each, reports A, B, BOTH, NEITHER or OPEN, and names the test that would separate them.
indahl-outside-rulerCheck one’s own work against a ruler the user did not build before it goes out.
indahl-number-checkCheck every number in a report, memo, deck or dashboard against its source. Each figure is traced and marked HELD, MOVED, NO_SOURCE or CANNOT TELL with the source line beside it.
indahl-quote-checkCheck every quotation in a draft, article or report against its source, word for word. Marks each VERBATIM, ALTERED, PARAPHRASE_IN_QUOTES, MISATTRIBUTED, NOT_FOUND or CANNOT TELL with the source text beside it.
indahl-source-checkCheck every citation, reference or link in a paper, report or answer: does it exist, does it say what the text claims, which version was read. Marks each SUPPORTS, PARTIAL, CONTRADICTS, SILENT, NOT_FOUND or CANNOT TELL.
indahl-controlsAudit a study’s or test’s positive and negative controls before it runs. Returns a control table and READY, FIX_CONTROLS or CANNOT TELL.
indahl-marginFor a sharp prediction, design or result, find how far its key parameter can move before the conclusion fails and compare that margin with the parameter’s stated uncertainty. Returns ROBUST, FRAGILE or CANNOT TELL with the break point.
indahl-correctRecord a correction beside the original, never over it. Produces a corrections ledger entry and a list of downstream places to update, each marked UPDATED, NOTIFIED, CANNOT_REACH or NOT_NEEDED.
indahl-clauseCheck the sentences that report a result for wording that claims more than the comparison showed. Returns each sentence as KEEP or REWORD with the exact replacement.

Details for the checks with scripts are on Plugins. Source and READMEs: claude-plugins in the public repository.
