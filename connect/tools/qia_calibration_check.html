CHECK IBM QUANTUM CALIBRATION BEFORE A RUN

qia_calibration_check

Check the calibration record IBM publishes for an IBM Quantum processor, for the qubits a circuit will use. With no time given it reads the newest record in the indahl.ai saved index, states when the index last read IBM successfully (the view is the one IBM's API gives the indahl.ai account) and how old the record's stamp is, and treats now as the run time; with a run time it reads the record in force then. The QIA Research Package rules are applied: STALE_AT_STAMP (T1, T2 or an error figure measured more than 24 h before the record's own stamp), STALE_AT_RUN (more than 24 h before the run time: the given time, or now when none is given), T2>2T1 (past the physical bound; ABOVE past 2.5, CANNOT TELL between 2 and 2.5), PAIR (T1 and T2 measured more than 24 h apart), ZERO and TINY error figures, FUTURE dates, and UNKNOWN for a figure that cannot be read. Returns each qubit's published figures with measurement dates, the flags in two groups (T1 and T2; error figures), and the unflagged qubits with the lowest published readout error. Outcome CLEAR, FLAGGED or CANNOT TELL; CANNOT TELL also when the index has not read the processor recently enough to know the record in force. The same rules run offline with pip install qia-check. Records cover up to 30 days before the newest save, which is printed.

Inputs

InputRequiredWhat it takes
processornoIBM processor, for example ibm_kingston. Call with no processor to list the processors with saved records.
qubitsnoQubits the circuit uses: "0,1,5" or a range "0-5". Empty checks every qubit.
atnoOptional run time (ISO 8601; no zone is read as UTC). Empty uses the newest record.
alternativesnoHow many lowest-readout-error unflagged qubits to list, 0 to 20. Default 8.

What it does with a request

Read-only. It reads data indahl.ai has already published and sends nothing onward. The server keeps nothing from the request. Each answer carries a signed receipt. How the server handles requests.
