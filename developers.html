DEVELOPERS · API, MCP and OpenAPI

Developer guide

indahl.ai serves the QIA calibration tools and checks on supplied material as read-only tools: over the Model Context Protocol for AI assistants and agents, and as plain JSON over HTTPS for scripts. No key, no account and nothing to install. One base address, one answer format.

MCP serverhttps://indahl.ai/mcp (streamable HTTP)
JSON APIhttps://indahl.ai/api/v1/<tool> (GET, query parameters)
OpenAPI 3.1https://indahl.ai/api/openapi.json
Server card/.well-known/mcp.json
Tool referenceEvery tool, what it returns · one page per tool
AuthNone. Read-only: no tool writes, sends or changes anything.

Quickstart

curl

curl "https://indahl.ai/api/v1/list_divisions"
curl "https://indahl.ai/api/v1/qia_calibration_check?processor=ibm_kingston&qubits=0,1"

Python

import requests

r = requests.get("https://indahl.ai/api/v1/qia_calibration_check", params={"processor": "ibm_kingston", "qubits": "0,1"}, timeout=30)
answer = r.json()
print(answer["source"], answer["read_at"])
print(answer["data"])

JavaScript

const r = await fetch("https://indahl.ai/api/v1/check_reported_statistics?text=" +
  encodeURIComponent("t(28) = 2.20, p = .036"));
const answer = await r.json();
console.log(answer.data);

Connect an assistant

ClaudeSettings, Connectors, add a custom connector with https://indahl.ai/mcp. Claude Code: claude mcp add --transport http indahl https://indahl.ai/mcp
ChatGPTSettings, Apps and Connectors, developer mode, create a connector with https://indahl.ai/mcp, no authentication.
Any MCP clientPoint a remote (streamable HTTP) MCP client at https://indahl.ai/mcp.

Every tool declares read-only, non-destructive hints and an output schema. Start with list_divisions.

The answer

Every tool returns the same envelope. Over MCP it arrives as structured content and as a text block; over the JSON API it is the response body.

{
  "source":    "where the data comes from (URL or named public record)",
  "read_at":   "when indahl.ai last read the source, ISO 8601 (the serve time when the tool computes on its input)",
  "served_at": "when this answer was served, ISO 8601",
  "terms":     "https://indahl.ai/terms",
  "use":       "what the data may be used for",
  "data":      { "...": "the tool result" }
}

Outcomes inside data are ABOVE, BELOW, CONSISTENT or CANNOT TELL, relative to what was stated. Nothing returned, refused and held are counted as their own outcomes, never folded into another. CANNOT TELL always carries its reason.

StatusMeaning
200The answer, as above.
400{"error": ...}: a required parameter is missing or not valid.
404{"error": "unknown tool", "see": ...}

Signed receipts

Over MCP, each answer carries a second text block: a receipt signed with the site’s Ed25519 key, binding the tool, the request arguments, the answer bytes and the server time. The public key is at /.well-known/jwks.json; how to check a receipt. A receipt proves indahl.ai produced this answer to this request at that time. It does not prove the answer is right.

Versions and terms

The JSON API is version 1 (/api/v1); the OpenAPI document carries its own version. Fields are added, not renamed or removed, within a version. Free to read and cite with attribution. Text and data mining and AI training are not permitted (terms). Data handling for the MCP server: security. Source: github.com/indahl-ai/indahl.ai. Questions go through Inquiry, in the menu below.
