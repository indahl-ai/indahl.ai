How we work

These are the checks the results are held to. Each one is also a free skill for Claude Code, so anyone can run it on their own work.

/plugin marketplace add indahl-ai/indahl.ai
/plugin install indahl-full@heuremen

Before the run

  • indahl-controls A test that cannot fail says nothing when it passes. Check the controls before the run, while it is cheap.
  • indahl-margin A prediction that breaks when one input moves by less than that input’s own uncertainty is not a prediction yet. Find the margin first.
  • indahl-prereg Seal the plan in git, and read from the git host’s own push record whether it came before the first run supplied.

Reading the result

  • indahl-cannot-tell A guess dressed as an answer costs more than a plain “not yet”. Four outcomes, never two: above, below, consistent, cannot tell.
  • indahl-both Most bad conclusions come from a second explanation dropped too early. Keep two readings open until the evidence separates them.
  • indahl-triangulate One reading is a perspective. Two give a difference. Three readings show where they agree and where they split. Agreement is not proof.

Before it goes out

  • indahl-outside-ruler The person who made the work cannot be its only check. A referee gets the raw material, not the summary.
  • indahl-number-check Every number read back against where it came from.
  • indahl-quote-check A paraphrase inside quotation marks is a misquote, however close.
  • indahl-source-check Each citation opened and read for whether it says what the text says it says.
  • indahl-clause The sentences that claim more than the comparison behind them, found before a reviewer finds them.

After it goes out

  • indahl-correct A correction goes beside the original, with who caught it and when.
  • indahl-readcheck The skill refuses to write a reading without its check block. The commit gate that enforces it ships in the version from the indahl.ai marketplace, not in the directory copy.

Big jobs

  • indahl-batch Work too large for one context window is split into batches, each done by a fresh worker against the same written checks.

Checking other people’s claims

  • indahl-standards A paper or claim checked against the Heuremen Standard claim codes, with quotes and four-state statuses.
  • indahl-eval-check A language-model evaluation claim, or an eval run, checked against the house eval checks.

The same checks on model training

Model training is read the same way: the held-out sets fixed in git before the run (the ordering is self-witnessed), every model scored on the same items, the paper as the unit when one paper gives several items, and no model kept until it beats the untouched model on both counts.
