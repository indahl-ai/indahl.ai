Reproduce

Check a release against the public repository

Each release writes a record at /build.json: the commit of the site source, the commit of the public repository that holds the same release, a fingerprint of everything the release deployed, the result line of every gate it passed, the time it shipped and a hash of every served page. The record is signed with the published key.

Check a release against the public repository

curl -s https://indahl.ai/build.json -o build.json
git clone https://github.com/indahl-ai/indahl.ai
cd indahl.ai
git checkout "$(python3 -c 'import json; print(json.load(open("../build.json"))["public_commit"])')"
python3 code/site/accountability.py pages-sha .
python3 -c 'import json; print(json.load(open("../build.json"))["pages_sha256"])'

The two lines printed last are equal when every served page in the public repository is byte for byte the page that release built. The hash is SHA-256 over the sorted list of each page path and its own SHA-256.

Compare the live site with the repository

python3 code/site/accountability.py compare-live .

This fetches each page from indahl.ai and prints any page whose bytes differ from the file in the repository. Pages the server fills at the moment of the request (the weekly page, the transparency counts, receipts read from storage) are listed as filled live and are not compared.

What the release check does not cover

The pages are built from desk data folders that the desk code reads from the public sources each desk names. The repository holds the build code in code/site, the desk code in code/, and the pages it produced. Rerunning a desk reads its sources again on a later day, so a rebuild matches a release where the sources have not changed since. The comparison above needs no rerun. The desk headlines are covered by the kits below.

Reproduce a desk headline

For each desk below, a kit holds the desk’s own scoring code, the inputs it read or the list of them with their sha256, and one command that recomputes the headline number and its outcome label offline. Before every release, every kit is run in an empty folder from its own contents. The release is refused if a kit does not print the headline it names, if the row the ledger keeps for the desk does not cover that headline (the same label and the number inside the row’s interval, or for a desk with no interval the same key fields), or if the live page has moved past it.

Where a source’s terms allow it, the kit includes the inputs. Where they do not, the kit lists each input file with its sha256 and the sources to fetch it from, and the kit is rerun on the kept copies. The live page can move inside the interval between releases. A move outside it or a change of label needs a new ledger row and a new kit.

Desks without a kit

These desks have no kit. The reason and what can be checked are listed for each.

  • CADA: The desk asks public DNS resolvers live whether they block fresh abuse listings. A resolver answer cannot be replayed. Each published copy of the feed has its sha256 on the TAPE chain, and the data pack holds the counts and outcomes.
  • HFLICENSE: The card is read from the Hugging Face API listing and each repository’s license file on the day of the read. Repositories change their files and the API answers with the current state. The desk page lists every repository that disagrees or is not comparable, with the tag and the file family, and the data pack holds the counts.
  • HOSTS: The headline is the count at the newest poll of OpenRouter, a live service whose answers cannot be replayed, and its flag test reads the 24 hours before the poll by the clock. Each poll is kept as parsed rows, not as the service’s answers. Each published copy of the feed has its sha256 on the TAPE chain, so any kept copy can be checked against what was published. The data pack holds the counts and outcomes.
  • PETROL: The card is a count of outcome words for the newest OPEC month, read from the OPEC Monthly Oil Market Report tables and the EIA weekly files as each was published. A later report replaces the month it covers. The desk page prints every member, its required level, the secondary-source figure and the revision width, and the data pack holds the rows.
  • RANK: Each US News figure is set beside a public record read one by one from state report cards, federal school and college data and schools’ own reports, sources that change on their own schedules. The desk page lists every figure with its source link and read date, and the data pack holds the rows.
  • REVISE: The headline compares the first BLS estimate with the most recent value, read from the BLS flat file on each run. The BLS table of first, second and third estimates is kept with its sha256. Until 10 Nov 2026 the flat file was not kept, so the published values cannot be replayed. From the next read on, each version of the flat file is kept by its sha256, and the start of its sha256 is in the feed. The feed names the sha256 of the BLS table it read, and the TAPE chain holds the sha256 of each published feed.
  • SOCIAL: The ad-spend reading matches Google’s political ads library to FEC filings, both read as they stood on the read date. Neither source keeps the earlier answer. The desk page lists every matched committee and cycle with its outcome, and the data pack holds the rows and the match keys.
  • TAPE: The headline is a clock, the time since the newest entry was chained. Each entry carries the hash of the entry before it.
  • TIME: The desk measures public time servers live against a GPS-disciplined clock. A time reading cannot be replayed. Each published copy of the feed has its sha256 on the TAPE chain, and the data pack holds the readings and outcomes.
  • UPTIME: The desk probes vendor services and their status pages live from two networks. A probe answer cannot be replayed. Each published copy of the feed has its sha256 on the TAPE chain, and the data pack holds the counts and outcomes.

To run a kit, clone the repository and run the command in the desk’s folder. The code that makes the kits and the release gate is reproduce/reproduce_kits.py.
