VAULT · Receipts and sealed files

Division: HERMES

The file never leaves the computer. The browser hashes it, seals it or opens it, and the only thing ever sent to indahl.ai is a 64-character hash, and only when a receipt button is pressed. indahl.ai keeps the hash and the time. No file is kept, scanned, hosted or released.

Get a receipt

A receipt proves that a file with this hash existed by this time. It joins the tape. It does not show who made the file or that it is true.

Check a receipt

Seal a file until a date

The browser encrypts the file to a future round of drand, the public randomness beacon run by independent organizations. The key for that round does not exist until drand publishes the round, so nobody can open the file before then. Not the owner, not indahl.ai, not drand. After it, anyone holding the sealed file can open it. The sealed file is saved to the computer. Keep the original, because a lost sealed file cannot be recovered.

Open a sealed file

What this does and does not do

indahl.ai never receives the file, the sealed file or a key. It cannot scan, host, find or release the file, and nothing here can be used to take it back. A shared sealed file is shared by the person who shares it. Do not seal material that is illegal to hold or share. indahl.ai cannot see it, and the law applies to the sender and to anyone it is passed to.

indahl.ai stores the hash and the time of each receipt. It does not store the network address, and its network provider keeps its own logs. Release times come from drand, so they do not depend on indahl.ai. If drand ever stopped publishing, a file sealed to a later round could not be opened. Files over 60 MB are refused.

Sealing uses tlock-js (npm), bundled into one file served from this site.
